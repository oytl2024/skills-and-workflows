# Knowledge Base Sink

这个文件定义导师互动模式结束后，如何把用户的学习成果沉淀到知识库文件中。

## 默认目录结构

优先使用下面的文件结构：

```text
知识库/
  <学科名>/
    第NN章/
      知识点与精髓.md
```

例如：

```text
知识库/
  国际金融/
    第04章/
      知识点与精髓.md
```

这样做的原因是：

- 先用普通 Markdown 文件就能稳定工作
- 以后迁移到 Obsidian 时，不需要重构内容
- 文件结构天然对应“学科 -> 章节 -> 知识点”

## 写入原则

只记录已经在互动中被澄清过、被纠正过、或被归纳为高价值结论的内容。

不要把整段对话原样塞进去，也不要把知识库写成第二份讲义。

## 文件格式

每个文件只保留“知识点 - 精髓”配对。建议格式如下：

```markdown
# 第NN章知识点与精髓

## 知识点：<名称>
精髓：<一句到数句，写清这个知识点最核心、最容易迁移、最值得反复记住的内容>

## 知识点：<名称>
精髓：<...>
```

## 精髓的写法

好的“精髓”应满足：

- 不是复述教材整段定义
- 不是零散结论堆砌
- 能直接提醒用户这个知识点最本质的理解抓手
- 尽量保留学科思维方式，而不是只保留表面结论

## 互动后的沉淀动作

每轮互动结束后：

1. 判断本轮聚焦了哪些知识点
2. 为每个知识点提炼最核心的一条或几条精髓
3. 写入对应章节的 `知识点与精髓.md`
4. 若该知识点已有记录，优先增补或修正，不要机械重复
