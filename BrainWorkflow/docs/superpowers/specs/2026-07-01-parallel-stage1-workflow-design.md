# Parallel Stage 1 Workflow Design

## Goal

Stage 1 must find a manually submit-ready WorldQuant BRAIN Alpha without relaxing checks. The workflow now prioritizes new datasets to reduce self/prod correlation risk, uses simple interpretable templates first, and escalates only promising results into optimization.

## Architecture

The workflow is split into assignable tasks generated by:

```bash
python -m wqb.cli plan-stage --workflow-stage scout --dataset-id search_interest,news21
```

Each task has a type, owner, inputs, outputs, forbidden actions, dependencies, and a promotion gate. This makes the process safe for subagents: data scouts can run independently, while diagnosis and submit checks remain centralized.

## Stage Flow

1. `result_recovery`: recover existing in-flight runs before any duplicate resubmission.
2. `data_scout`: build a 30-Alpha candidate batch, then run one new dataset with conservative economic templates and full artifact logging. Prefer one template across many new fields before expanding variants on one field.
3. `diagnosis`: compare checked results and decide candidate, near-miss, discard, or next Scout.
4. `repair`: make 4-8 targeted variants only when `is_near_miss()` is true.
5. `submit_check`: write `candidates.csv` only after clean hard checks. It never submits.
6. `knowledge_update`: convert repeated issues into documented workflow rules.

## Error Handling

Platform errors are mapped to workflow actions in `wqb.research_workflow.workflow_action_for_platform_issue()`. Known mappings include missing regular peers, VECTOR/event operator errors, broad field search, recoverable network failures, rate limits, and weak Scout branches.

## Testing

The behavior is covered in `tests/test_research_workflow.py` and `tests/test_cli.py`. The tests verify stage caps, Scout simplicity, near-miss gating, assignable task plans, and issue-to-action rules.
