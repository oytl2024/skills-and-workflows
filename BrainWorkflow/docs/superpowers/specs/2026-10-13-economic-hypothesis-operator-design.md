# 经济假设驱动的模板与算符知识设计

日期：2026-10-13（Asia/Shanghai）。状态：待用户审阅的正式设计，尚未实施。

## 1. 目标与边界

让研究从“对字段套常见表达式”转向“解释数据、提出有竞争解释的条件假设、用最小表达式检验”。丰富的是整批研究的经济机制和算符职责，不是单个 Alpha 的嵌套数量。

用户已确认：整批多样，单个保持简洁；知识编译应探索算符在不同情况下的用途；可以由数据或算符触发想法，但最终必须落实到资产影响的可检验假设。

本设计只调整知识编译、模板表达与研究计划输入，不重写 Orchestrator 阶段，不改变已成熟的回测恢复、Repair、检查顺序、资格判定或研究记录流程。Repair 四句简报不变，新增假设卡通过引用供其读取。最终 Alpha 提交仍单独授权。

不新增知识库顶层目录、不部署图数据库、不引入无限递归发散、不以算符数量作为收益目标。此次文档批准不代表已有知识完成编译或运行代码具备下述能力。

## 2. 当前实现与缺口

核对位置：`wqb/operator_semantics.py`、`template_library.py`、`knowledge_experience_compile.py`、`research_planning.py`、`generator.py`。

- 当前机器算符账本有107条，只有3条带工作流用途和修复方向；存在名称与分类，不等于已经理解所有算符。
- 当前模板记录已有经济假设、数据语义、算符组合、放弃条件和模板族等字段，但现有内容未充分填充；人读模板页仍显示没有模板族。
- 现有知识编译主要进行合并和统计，不能将其称为已经实现了模型辅助的条件用途研究。
- 当前研究模型主要选择既定模板的持有衰减参数，不负责完整的经济假设创造；当前生成器仅接受单字段和窗口占位符。

因此需要同时补齐“可追溯的知识内容”和“执行器实际消费它的接口”，不能只写丰富的 wiki 而让运行仍使用旧模板字符串。

## 3. 主流程

```text
原始平台定义、字段说明、研究记录、用户输入
  -> 单独启动知识维护
  -> 校验基础定义与数据语义
  -> 有界模型编译：条件用途与竞争假设
  -> 确定性校验、去重、证据分级
  -> 发布 machine 资源与简洁 wiki
  -> 用户选 Option Card 并 Start
  -> 冻结本次知识快照
  -> 按研究目标选择不同机制的可执行假设
  -> 绑定真实可用字段与必要算符、构造最多30个候选
  -> 沿用 Scout / Seed / Discovery / Repair / 检查与经验记录
```

知识维护继续有两种入口：研究后总结已有记录；用户单独要求更新平台资料后，再编译新资料。研究 Start 不隐式联网抓知识，也不每次全量重新编译。已开始的任务不自动采用后来编译出的规则或模板。

## 4. 三类证据必须分开

| 类型 | 含义 | 可以支持什么 |
| --- | --- | --- |
| 平台事实 `documented` | 有原始来源、捕获日期和内容摘要校验的定义或字段说明 | 语法、输入输出类型、数据粒度、可用范围 |
| 研究假设 `hypothesis` | 推导出的可能作用机制和适用条件 | 值得测试，不能宣称已有效或已低相关 |
| 实测经验 `measured` | 能定位到表达式、设置、结果和测试记录 | 该条件下的观测结果，不代表普遍因果关系 |

证据等级与模板生命周期分开：一个语法正确、未回测的假设可成为 Scout 输入，但不是成功模板；一个回测较好的模板也不能替代最终检查。

每条推断关联自己的来源和实验引用，不能用一个有来源的算符名称给整段经济推断背书。没有实验时明确写“未验证”；没有官方定义时不能凭名称补造精确语义。编译时间不更新原材料捕获时间，不自动延长有效期。

## 5. 数据语义是前置条件

字段用于某个假设前，至少需要确认：它测量什么、观察粒度、单位或尺度、更新频率与可用时点、缺失值含义，以及所属地区／延迟／股票池的可用证据。

对 VECTOR 还须确认每个元素代表什么，归约操作后保留或丢失了什么。VECTOR 不等于事件列表，元素数不自动等于新闻数，平均值也不自动代表正面信息。

未知的信息保留为未知。仅缺少非必要说明可降置信度；如果缺少假设依赖的必要语义，则该绑定不可执行，保留研究想法但不提交回测。不能为了填满批次而换成无关的价格成交量表达式。

## 6. 算符知识：从名称到条件用途

沿用 `machine/operator_ledger.jsonl`，扩展 `OperatorSemanticRecord` 的可选字段，不建立第二个同名权威账本。已有字段和旧记录保持兼容。

每个算符的编译内容包括：

| 内容 | 要回答的问题 |
| --- | --- |
| 数学定义与类型 | 输入输出是什么，支持哪些参数，平台说明是什么？ |
| 信息变化 | 改变尺度、方向、分布、时间结构还是共同暴露；丢失了什么？ |
| 条件用途 | 哪种数据性质或研究问题下可能有用，为什么？ |
| 失败与误用 | 什么时候会放大噪声、损失方向、引入换手或误解缺失值？ |
| 组合职责 | 在哪些假设中担任信号提取、确认、条件、归一化或风险处理？ |
| 证据 | 哪部分来自定义、哪部分是假设、哪部分有实验？ |

`conditional_uses` 使用结构化列表，每项保存适用条件、用途、失效风险和证据引用；模型可提出少量高价值用途，不要求机械地为每个算符编满固定数量。

基础算术和类型转换可以只有实现层用途，不强行赋予独立经济机制。权重分布调整不能被描述成自动提高预测能力；数学上的风险剥离也不能在无证据时描述成已提高净收益。

## 7. 假设卡与模板库

沿用 `machine/template_library.jsonl` 和 `TemplateRecord`；增量扩展可选的 `hypothesis_card`、`operator_roles`、`input_slots` 和证据字段。具体序列化校验由实施计划落实，旧单字段模板不被静默改义。

一张假设卡包含以下七项，每项正文一句话；长证据通过本地引用读取：

1. 数据含义：当前信号实际测量什么。
2. 作用机制：为什么可能影响未来相对收益。
3. 成立条件：机制需要什么市场、数据或时间条件。
4. 竞争解释：同一现象还有哪种合理解释。
5. 可观察预测：如果假设成立，应看到什么可检验现象。
6. 算符职责：每个必要算符分别完成什么工作。
7. 否定条件：什么结果会削弱或否定本次假设。

假设ID、版本、模板族、方向、周期和证据状态属于机器元数据，不塞进长提示词。模板修改产生新版本；既有实验、资格证据和活动任务不被覆盖。

示例仅用于说明设计：当字段被证实为新闻事件计数时，数量上升可分别提出信息尚未反映、注意力过热、共同市场事件三类假设；前者需要方向与价格反应证据，第二类需要短暂性与先前反应证据，第三类需要同组比较证据。三者都未因描述合理而得到验证，也不必一次同时测试。

## 8. 有界发散与收敛

允许两个入口：由数据现象触发，或由算符的数学性质触发。算符入口也必须回答“该变换为什么适合这类数据与资产机制”，不能停在可组合表达式上。

建议设计默认：每个触发点最多保留3个竞争机制，每个机制最多保留2个有区分价值的条件分支；不递归生成分支的分支。算符条件用途每次优先补缺，不重复全面重写已有可信内容。这些上限作为可配置策略，不能埋在提示词中。

收敛时依次筛掉：必要语义未知、不可观测条件、前视风险、没有区分预测、无法在复杂度限制内表达、已有等价表达式、超过本次原始权限或预算的方案。材料不足时少生成，不凑足30。

## 9. 复杂度与整批多样性

单个 Alpha 先用足以检验核心假设的最小表达式；只有观察到信号且有明确诊断时，才交由既有优化流程增加处理。

保留当前 Scout 单行、嵌套深度和数值参数限制，不因创新放宽。实施时额外记录实际函数调用总数和算符职责数；本 spec 不擅自增加尚未确认的全局调用数阈值。算符简洁性由现有硬限制与最小必要职责共同约束，不能把多次调用同一函数算成一次来隐藏复杂度。

批次在合法候选中优先覆盖不同经济机制，其次覆盖数据语义、条件、算符职责和历史使用差异；相同机制的小窗口变化仍属于同族。模型提供可审计的推荐，确定性选择器执行去重、复杂度和预算约束。字段或模板较新只能作为拥挤度先验，不能替代 SELF／PROD 检查。

不强制每批覆盖所有类别，不用无关算符补多样性。批次大小为可执行候选数与当前合法上限的较小值，最多30，并服从剩余额度和显式轮数上限。

## 10. 必要的执行接口

新假设有时需要信号、确认、风险等不同数据角色。为避免描述丰富但执行仍只读一个字段，新增显式版本的输入槽契约：每个槽声明角色、所需语义、原始类型、归约需求与可用范围。

旧版本继续只接受 `{field}` 和 `{window}`；新版本使用经校验的命名槽绑定。绑定器输出无未解析槽位的固定经济内核，再交给生成器做已批准的有限参数变化。不得用无约束字符串替换模拟类型检查，也不得由模型输出任意可执行代码。

确定性验证器检查实际字段存在、同一研究范围可用、算符参数与类型兼容、归约位置正确、无前视、复杂度与表达式身份。显式向量归约接收原始向量，不能再包默认归约；多参数归约也必须覆盖。

研究计划保存假设ID／版本、全部字段绑定、算符角色、证据摘要校验、被采用的模型决定和选择理由。现有表达式＋设置的模拟身份不变：两个不同叙事生成同一表达式时仍去重，不能重复提交并当成两份独立证据。

## 11. 模块职责与 AI 介入

| 模块 | 输入与输出 | 实现边界 |
| --- | --- | --- |
| `operator_semantics.py` | 原始定义与已有经验 → 条件用途账本 | 扩展现有记录，保留来源与未知项 |
| `template_library.py` | 假设卡与模板 → 有版本的可执行模板资源 | 保存角色、槽位和证据，不直接回测 |
| 知识编译入口与协调器 | 本地材料包 → 经验证的资源更新 | 在 `cli.py` 现有知识维护入口及 `knowledge_vault_migration.py` 编译链中接入独立语义任务；复用受限只读 AI 适配器，模型只返回结构化建议，编译器负责发布；不在普通运行中重复执行历史迁移 |
| `knowledge_experience_compile.py` | 已验证资源与记录 → 人读 wiki | 解释条件、反例和经验，不只是计数摘要 |
| `research_planning.py` | 冻结知识快照与目标 → 本轮消费的假设选择 | AI 做高价值假设判断，确定性代码执行约束 |
| 生成器及绑定验证器 | 固定内核与字段绑定 → 计划候选 | 不联网发现字段，不擅自替换机制或放宽限制 |
| 现有记录与 compile 入口 | 完整实验轨迹 → 后续可复用经验 | 正负结果都保留，未完成结果不能当失败或成功 |

AI 用在条件用途提炼、竞争假设生成、有限方案选择和结果解释；字段查找、去重、计数、预算、轮询、校验和发布不需要模型。已有常规 Repair 决策链不被本设计替换。

模型输入是简短卡片加有范围、有摘要校验的材料索引；按需读取相关本地定义，不把整个 data ledger 或全部研究历史塞进提示词。不要求输出隐含思维过程，只保存可审核的假设、证据、理由和决定。子代理沿用 reasoning effort 不超过 medium 的规则。

知识编译每份材料摘要只处理一次；缓存键覆盖来源内容、目标结构版本和模型任务版本。来源更新、结构变化或经验冲突才重算相关条目。失败和被拒输出保留诊断，但不污染可运行资源。

## 12. 知识库编排与发布

- `raw/`：继续按现有平台、研究、用户输入等来源分类，保存原始材料；不能把模型发散写成平台原文。
- `machine/`：供程序读取的权威结构资源，允许 JSON／JSONL，不要求人直接阅读大账本。
- `wiki/20_data_semantics.md`：解释常用数据的语义、观察粒度和误读风险。
- `wiki/30_template_and_operator_patterns.md`：按经济机制展示假设卡、最小组合、条件与反例，关联算符用途和研究案例。
- `wiki/40_benchmark_and_repair_rules.md`：沉淀经验证的判断，不自动采纳新的 benchmark 规则。
- `wiki/60_research_cases/`：继续提供人可读的研究优化轨迹；不复制全量机器账本到 wiki。

先在暂存区域生成，再校验引用、结构、事实／假设标签、类型和旧资源兼容性；全部通过后按一致版本发布资源清单，读者不可见混合半版本。失败保留最后一个有效版本和失败状态，不能伪造新鲜度。大篇幅资料按既有报告或引用浏览，不重新创建历史目录层级。

编译后的结构清洁检查仍是发布条件；来源冲突、无效链接、旧版结构混入或模板语义不兼容时，不能只写一份新页面而留下两套权威资源。

## 13. 失败、迁移与权限

新字段或算符缺少必要定义：保留想法并报告缺口，不自动联网抓取。模型不可用、输出不合法或材料被改动：停止该条编译／计划，保留诊断和通知状态，不每次重启重复调用模型。

旧记录缺新字段时标为语义待补充，而不是默认“已理解”或直接删除。先补入可验证内容，再把新模板作为未来任务的计划输入；不追溯修改正在运行的 Start 快照。已合格 Alpha 的检查证据保持原身份和独立有效期。

模型可以提出模板假设，不可以自动修改 benchmark、复杂度阈值、研究权限、预算或最终提交规则；这些仍走提案与用户决定。Stop、未知 POST 保护、相关性检查后置和事件驱动维护通知继续有效。

## 14. 验收

1. 新旧记录可读写往返；旧语义与表达式身份不变，新字段不会在编译合并时丢失。
2. 每个用于计划的算符有可定位定义或明确缺口；条件用途不能被默认提升为实测结论。
3. VECTOR 非事件列表、多参数归约、未知单位、时点不明和不匹配研究范围都有拒绝或降级测试。
4. 同一触发点能产生有不同预测／否定条件的竞争假设，而非只改窗口；同义机制和等价表达式会合并。
5. 同等证据下，简单有效表达优于无必要的算符堆叠；整批多样性不依赖每个表达式强行跨类别。
6. 模型决定真实进入计划和候选来源；缺少绑定证据时不能仅凭 readiness=True 就声称已消费知识。
7. 同一材料和任务重启不重复模型调用、重复发布或重复 POST；来源变化只重编译受影响条目。
8. 小于30个、剩余7次、零候选、无合适模板、Stop、模型失败、429与未知结果均沿用安全恢复和通知。
9. 一次离线集成覆盖：材料编译 → 多机制假设 → 字段绑定 → Scout → 既有后续阶段 → 研究记录 → 再编译；使用明确标识的假平台／假模型证据，不写入真实研究结果。
10. 人读 wiki 能回答“为何试这个模板、何时不适用、哪些已验证”，不再只是算符／模板数量表；结构检查保持通过。

研究质量报告同时记录机制族覆盖、可执行绑定比例、拒绝原因、重复率、模型缓存命中、近阈值信号和样本内／可用样本外证据。多次尝试数量与选择过程必须保留；样本内改进不能自动升级为稳健规律，换手变化也不等于已测出真实交易成本。

以上验收证明工作流契约，不保证产生可提交 Alpha。真实平台回测和最终提交仍依照各自授权与预算。
