# Goal-Scoped Start Preparation And Explicit Knowledge Refresh

Status: interaction contract approved; integration design for review, not implemented.

## Approved Multiplier Amendment (Nov10)

Latest user decision supersedes automatic Theme feasibility for the Multiplier
card: user selects Region/Delay, reuses a platform-valid configured Universe or
selects one. Start prepares missing exact-scope fields and compiles before the
normal research path. Activity/multiplier judgment belongs to the user; the
application does not certify theme eligibility. Stop/authority and other goals
remain independent. Implement this narrowed path first using the manual-scope
plan, without requiring the blocked authenticated support browser.

## User Contract

Every displayed research goal can be selected and started. A goal requiring
preparation runs that preparation first, rather than disabling the card or
silently substituting an unrelated ordinary research mission. The user operates
Option selection and Start/Stop. Final Alpha submission remains separately
authorized. Selecting Start authorizes only the selected goal's necessary bounded
read-only platform acquisition and authentication, local compilation and research
within unchanged model/simulation/runtime limits. This new contract replaces the
older absolute requirement for a separate capture request only within that
explicit selected-goal preparation; unrelated full-platform refresh stays separate.

This implementation session does not authorize actual platform/model/research
calls. Development/acceptance uses offline injected transport/model fixtures.

## Two Independent Maintenance Uses

1. Research learning: compile saved experiments, metric/repair traces and reusable
   experience after research. No platform access is necessary.
2. Platform refresh: explicitly acquire requested rules/operators/Learn/field
   metadata into raw, update indexes, compile machine/wiki and validate output.
   An update-only request never implicitly starts research.

Goal preparation may invoke a bounded subset of use2, then continue the selected
research automatically. It is not full-vault recapture or a new agent framework.
Global scientific-resource changes do not alter already sealed execution packages.

## End-To-End Path

```text
Select goal + Start
 -> persist preparation authority and Stop revision before network/model work
 -> inspect local goal prerequisites
 -> reuse valid evidence; fetch only missing/stale/goal-current required sources
 -> persist raw/provenance and compile changed resources locally
 -> determine activity eligibility and exact scope from verified facts
 -> freeze resolved goal context and hand off once to existing Start preflight
 -> initial AI experiment-tree planning
 -> existing Scout/Seed/deterministic Repair/check/record/retirement
```

Preparatory information is not treated as a known scientific fact merely because
it was downloaded. Unknown semantics remain unknown, with no new economic
whitelist. Syntax/types/tree standards and authority/accounting remain unchanged.

## Goal-Specific Behavior

- Genius/Osmosis: retain current exact-scope binding and normal local readiness.
- Power Pool: read board facts and rules; pick a compatible eligible board/scope
  deterministically using current planner ranking and explicit tie-breaks. Bind
  board constraints to the frozen research goal, not just its display title.
- Theme: resolve a currently active theme and its actual field/scope requirements;
  do not reinterpret generic multiplier text as an active theme.
- Competition: verify dates, participation/submission eligibility and alpha type.
  Reuse only a supported executor. Unsupported Python/other execution paths are
  real implementation gaps, not fabricated platform prohibition or success.

Expired/no eligible activity yields an explicit completed-unavailable outcome
and updated options, not a false research success. Missing implementation or
unresolvable contracts produce maintenance evidence, not an endless wait.

## Safety And Efficiency

- Persist request/attempt/capture/compile/handoff identities; replay completed work
  and retain partial progress instead of repeatedly recapturing.
- Preparation uses configured finite request/time/field bounds and local cache;
  no implicit all-region/all-Learn capture per Start. Exact limits and accounting
  are implementation-plan inputs, exposed centrally rather than hidden constants.
- Stop is acknowledged durably before more capture/model/simulation work; callbacks
  and restarts cannot override it. In-flight reads may finish and be recorded but
  cannot commit a research handoff after Stop.
- Keep activity deadlines, resource age, account eligibility and simulation quotas
  independent. Compilation preserves original capture dates and partial coverage.
- No arbitrary shell/URL/model tool execution from activity text. Data is data.
- Scope resolved during preparation must be displayed and frozen before research;
  a more general goal cannot expand the originally selected/configured scope
  authority silently. Eligible choices outside that authority remain explicit.

## Standalone Commands And Product Gaps

Existing tools include `scripts/capture_learn_material.py` (non-course Learn and
operators), `capture-platform-data-fields`, `compile-data-ledger`,
`compile-operator-semantics`, `compile-research-records`, `compile-knowledge` and
`knowledge-health-check`. `plan-research-options` refreshes incentive snapshots
and option cards but is not a complete raw-capture command. Broad field discovery
uses `discover-data-scope-matrix` and a stratified capture plan; sampling is not
catalog completeness. Do not advertise a unified one-command full refresh before
it exists. Semantic-model enrichment is separate and requires an explicit model
budget; ordinary scripted compilation does not imply all facts were inferred.

## Acceptance

tests for all goals, including unavailable/unsupported cases. Cover stale inputs,
partial capture, cooldown/restart, duplicate commands, Stop at every boundary,
unknown outcomes, source mutation, missing activity facts and no permission

not merely enabled Start. Preserve original old-run authority and sealed packages.
Full regression and verified installed-source checks precede delivery; Git sync
