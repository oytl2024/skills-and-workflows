# General Delay-1 MATRIX Timing

Status: proposed for approval; design and read-only premise validation only.
Scope: extend the existing source-backed timing resolver, not the Orchestrator,
research budgets, model framework or final submission authority.

## Problem And Actual Evidence

The existing `regular_delay_1` v3 contract recognizes a source-authenticated
classification table or a named ordinary/Fast-D1 comparison. This protects the
M1 example, but its field-specific comparison cannot classify arbitrary fields.
An absent contract therefore means unclassified, not proven unusable data.

The authorized Nov5 capture returned 104 operator records and 65 exact-scope
USA/Delay1/TOP3000 fields: 16 MATRIX, 49 VECTOR. All have positive reported
coverage. Current source compilation records 65 measured field observations,
while the catalog remains partial. None has `available_at`, `timing_contract`
or `vector_grain`. The active semantic release still has one verified operator
definition (`ts_delta`); a catalog record is not a typed executable definition.

Local premise validation authenticated the existing Oct15 Simulation Settings
source and the Nov5 Fast D1 source through `_material`. All 16 MATRIX records
match the captured scope and lack the `_fast_d1` suffix. This establishes a
candidate population, not permission to trade, simulate or claim PIT safety.
Exact evidence paths and results are in the Nov5 source-refresh receipt and
the output timing-design validation record; no new model job is involved.

## Chosen Direction

Keep the named contract unchanged. Add one versioned, project-owned derivation
rule using the same contract envelope and premise verification machinery:

1. Authenticate an official automatic-Delay1 policy statement.
2. Authenticate the official Fast D1 naming rule, including its scope and
   qualifications. Do not infer a universal rule from the `snt_buzz` example.
3. Authenticate the actual field/dataset identity, MATRIX type and exact
   instrument/region/delay/universe tuple from `/data-fields` provenance.
4. Derive ordinary Delay1 classification only inside the documented policy's
   applicability, where the field is not Fast D1 and no explicit source fact
   conflicts. Bind the derivation to those exact source hashes and rule version.

The logical step from the naming rule to ordinary classification must be
reviewed against the full official context, not accepted merely because a name
lacks a suffix. If the source does not establish a complete ordinary/Fast-D1
partition for the requested scope, return `classification_not_established`.
Do not add an undocumented default to make the acceptance count reach 16.

An alternative is continuing per-field named tables. It is retained for old
contracts but rejected as the general design: it requires recurring manual
classification and does not scale with a source-authenticated catalog.

## Output And Rejections

Return either a contract plus derivation evidence, or a structured reason.
Keep `kind=platform_execution_policy` and `historical_pit_verified=false`.
No invented publication timestamp, effective frequency, units or causal claim.
The experiment is governed by platform execution timing, not independently
proven vendor historical point-in-time correctness.

Reject unsupported Delay0, Fast D1, VECTOR/GROUP, missing identity/type/scope,
future/stale or changed sources, unknown rule versions, contradictory cutoff
facts, mismatched generations and insufficient official applicability. Unknown
metadata stays unknown. In particular, do not promote the 49 VECTOR records
based on a generic tutorial without the required grain/operator evidence.

Keep positive numerical coverage, source-byte certification, semantic binding,
Seed, Repair, correlation, Stop and resource/submission authority unchanged.

## Minimal Integration

- `resource_evidence.py`: versioned derivation/resolution alongside the existing
  named rule; reuse source, receipt and premise verification.
- `data_ledger_compile.py`: explicit compile-time attachment to matching fields;
  do not derive contracts during Start or mutate frozen run context.
- `preplanned_start.py`: only if needed, select independently validated fields
  before grouping/capping so one unsupported field does not hide valid peers.
  Never drop a rejection silently or invent compatibility.
- Existing tests and maintenance reports: add cases and counts. No new service,
  database authority, Agent framework, state machine or routine UI gate.

First actual acceptance scope is the captured USA/Delay1/TOP3000 cohort. Other
regions and universes require their own captured, valid scope evidence; this is
not blanket global availability. Operator-library expansion is separate and is
not authorized by this timing design or a zero-model local compile.

## Validation And Rollout Boundary

TDD: supported ordinary case; another field without a named example; renamed or
Fast suffix; conflicting structured timing; stale/future/tampered source; wrong
scope/type/generation; incomplete policy context; old-v3 compatibility; preserved
Stop/quotas and no implicit calls. Reconstruct a contract from verified premises
and reject a modified proof. Measure accepted/rejected counts without targets.

Then verify the actual cohort through the existing compiler and selected-resource
consumer, report remaining timing/grain/operator gaps, full offline regression,
Git sync and loaded-version acceptance. Publishing semantic definitions, new
model jobs, research Start and final Alpha submission retain their own boundary.
Until this document and its implementation plan are approved, production timing
behavior remains unchanged; the current Console must show the real blocker.
