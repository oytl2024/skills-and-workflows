# Script-Owned Execution Packages And Storage Retirement

Approved: user confirmed the module/retention boundary on Nov9, then clarified
that scripts, not AI, generate execution packages. This records that agreement;
it is not permission to start research, call WQB/models or delete sensitive data.

## Scope

Complete surplus-artifact retirement without breaking current/rollback apps,
historical identities or recovery evidence. New research plans become self-contained
after validated tree freeze. On completion of the tree AND its derived Seed/Repair
work, retain necessary scientific summaries and collect heavy execution inputs.
No new Agent framework or alternative executor. Reuse the existing tree, driver,
readiness, Repair, archive, locking and Console projection contracts.

AI supplies only structured designs/tree, data-characteristic annotations and
references to candidate Repair resources. Scripts authenticate facts, resolve
existing rules, compile expressions, build/seal the package, execute and retire.
AI never chooses filesystem paths, permissions, budgets or deletion policy.
Facts, measured characteristics, hypotheses and unknowns remain distinct.

End-to-end: knowledge -> AI tree/annotations -> deterministic compile and seal ->
existing script execution -> complete derived work/recording -> durable summary ->
retirement -> exact-path collection. Next planning cycle may read updated knowledge.

## Package Contract

Use an explicit version in frozen NEW Start policy. Legacy runs never gain it
from a file appearing or a new global setting. Freeze validates existing raw
certificates and compiler outputs once; subsequent execution validates owner,
immutable local bytes, scope, identities and seal without reopening global data,
operator, semantic-release or source catalogs. Do not bypass AST/tree validation.

Prefer existing selected run-local snapshot/attachments plus a compact seal over
another copy of the vault. Deduplicate repeated material or compress it within
existing byte bounds. Preserve source dates and provenance; global changes do not
rewrite a running plan. Do not pretend frozen acceptance is a fresh platform check.

Scripts derive actionable Repair traits from documented facts and existing rules.
AI annotations may refer to known facts/unknowns/hypotheses and existing rule IDs;
they cannot promote guesses to facts, authorize new transformations, change grids
or overwrite the canonical ledger. Keep the current output shape for old workers.

Research decisions after freeze depend on package plus measured results/history.
Stop, shared dedup/accounting, in-flight reconciliation, current correlation/check
validity and final submission approval intentionally remain live independent state.
Research-record/candidate publication may write outcomes to the vault; that is not
permission to reload mutable knowledge for scientific decisions.

## Terminal And Retention Contract

Eligible only when tree routing is final, all selected Seed/Repair work is final,
research recording/qualified-candidate preservation is durable, and no unknown POST,
pending simulation/check or required recovery is outstanding. Pause, Stop, cooldown,
daily/runtime-budget waits, maintenance blocks and mere Scout completion are NOT
terminal. Never infer completion from artifact age alone.

Retain a bounded exact summary: hypothesis/conditions, node/branch topology,
expressions/settings and immutable identities, actual periods/metrics/checks,
accepted/rejected/rollback trajectory, selected kernel and finite-search stop
reason. Preserve qualified unsubmitted IDs and raw eligibility evidence/time,
submission history, lifetime/daily accounting, approvals and recovery provenance.
Retirement is not Alpha submission or evidence-validity renewal.

Transaction: lock/revalidate -> publish verified summary -> commit retirement
receipt -> collect only named owned heavy inputs -> record actual reclaimed bytes.
Crash/retry is idempotent. A prepared intent cannot hide the active payload. A
committed retired tree is read-only, not resumable; its summary remains viewable.
Never overwrite or erase original authority/accounting to make cleanup succeed.
Unique historical evidence requires lossless archival/read compatibility before
physical payload removal. Do not retain entire finished vault copies indefinitely.

Cleanup faults have durable specific evidence; they must not fabricate scientific
failure or trigger another model. Reconcile through existing scripted maintenance
entry points. An explicit authority/source problem remains visible, not waived.

## Historical Collection

Use existing `semantic_inventory_archive.py` and derivative lifecycle where
possible. Separate an actual active consumer from a documentary reference; all
remaining consumers must resolve authenticated archived bytes before collection.
Archive is historical evidence, not a second knowledge authority or new execution
permission. Unfinished/active tasks and unique facts remain protected.

For old run-local knowledge copies, verify no writer/in-flight operation, retain
identity/receipt evidence and provide lossless historical read/restore compatibility
before removing expanded copies. Preserve original timestamps and scope. No blanket
`runs/` deletion. Shared duplicate data should not be copied into every new task.

Keep installed/current/one verified rollback distribution and small source/proof
records. Collect obsolete build/test payloads through explicit manifests after Git
sync. Browser/profile paths need separate named approval; no credential/session
deletion is inferred from this spec. Dependencies used for runtime/rebuild stay.

## Verification And Release

TDD: freeze provenance, no global catalog reads after freeze, actual tree -> Seed
-> Repair parity, Pause/in-flight refusal, two-lane isolation, tampering and crash
recovery, terminal summary UI and candidate-cache reuse. Old-mode tests unchanged.
Historical archive integrity, exact references, idempotent collect/restore and
adversarial path/link tests precede real collection.

All implementation/tests offline. Real collection uses audited exact paths only
after passing regressions and verified Git sync; sensitive permissions stay named.
Full regression, source fingerprint, native build/loaded-version/action tests and
cleanup-outcome sync are required. Report any protected/external remaining blocker
honestly; never equate a tested primitive with deployed automatic collection.

Only exact new frozen execution_package_version=1 opts in. The installed app and
existing runs are not switched merely because these source files exist. Necessary
scientific summaries are not a replacement for immutable authority or raw check
evidence; unique archived bytes remain recoverable without granting execution.

Reference-closure optimization is independent of resource admission: a bounded
process-local cache remembers only complete successful scans. Every invocation
still enumerates owners and hashes current bytes; unchanged certified files can
skip repeated JSON traversal. Changed/new files and partial/failed scans do not
qualify. Generic scan defaults remain unchanged; large retirement scans use a
900-second local processing bound instead of180, without changing research or
platform budgets or treating timeout as success.
