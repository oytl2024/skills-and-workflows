# Structured Economic Template Upgrade

Status: design for user review; implementation not started.

## Intent And Boundaries

Upgrade the existing V2 hypothesis path, not the Orchestrator or API executor. AI proposes mechanisms and observational experiments; deterministic code constructs templates. Reuse semantic_contracts, semantic_compilation, template_binding, semantic_publication, hypothesis_selection and research_planning. No new Agent framework, service, parallel library or authoritative knowledge ledger.

Routine interaction remains Option Card plus Start/Stop. Online capture, knowledge maintenance and final Alpha submission retain existing separate authority. All development and acceptance use offline fixtures or frozen, non-sensitive source copies. No production model invocation, platform request, research resume, budget change or real-vault mutation follows from test execution.

## Existing Capability And Real Gaps

The current implementation has seven-sentence HypothesisCard, typed InputSlot/OperatorRole, AST binding, immutable paired publication, bounded model decisions, frozen plans and legacy recovery. Semantic model output still includes skeleton strings; Scout expands allowed windows, decay and neutralization before selection. Existing case compilation does not provide paired mechanism evidence.

Read-only real-vault audit on 2026-10-14 found 107 legacy operator rows without typed definitions/conditional uses/evidence refs, four legacy templates without V2 cards/slots, and 153513 scope-specific data rows with descriptions but without units/vector_grain/available_at. There is no active semantic release. Existing raw operator Markdown contains syntax/descriptions not consumed by the legacy JSON-only reader. Dataset categories are stringified objects. Some seed provenance points at missing historical paths. The audited July field raw capture itself lacks required timing/grain/unit metadata. Creation or capture dates must not substitute for point-in-time availability.

Therefore compiler delivery and usable knowledge delivery are separate acceptance gates. No global readiness claim based solely on row counts or freshness is permitted.

## Functional Data Flow

Knowledge maintenance: indexed source facts and bounded relevant research evidence -> AI design proposal -> strict validator -> deterministic compiler and binder -> immutable design/experiment receipts -> existing review/publication boundary.

Research: newly frozen reviewed templates and experiment receipts -> feature-flagged Scout pairs -> existing measured Seed, Discovery, backtest, Repair and checks -> original research records. No in-flight snapshot replacement or automatic publishing into a running mission.

## Hypothesis Generation

A data meaning or operator use is the trigger, not a formula. AI explores applicable conditions, distinct economic mechanisms, competing explanations, observable predictions and falsification. It identifies needed data roles and operator duties only after stating the hypothesis. Preserve existing SemanticPolicy defaults: at most three mechanisms and two condition branches per mechanism, never fill missing branches for counts. Batch diversity is across mechanisms; individual Alphas stay simple.

Conditions must either be measurable using sourced resources, delimit interpretation/universe explicitly, or be labelled unidentifiable. Narrative conditions are not executable filters. Do not claim low correlation from novelty; actual correlation checks remain authoritative.

## M1: Structured Design And Deterministic Compilation

Add one focused hypothesis_design module unless implementation reveals a justified smaller placement. Public pure interfaces are design_output_schema(), validate_hypothesis_design(answer, evidence_pack), and compile_hypothesis_design(design, resources, scope). Inputs/outputs are strict JSON-compatible dictionaries with versioned schemas; compiler results are compiled drafts or explicit diagnostic rejections, not published records.

Design fields: stable mechanism family; rationale; prediction direction; conditions; alternative explanation; falsification; field-role requirements; restricted feature plan; baseline and at most one primary treatment; controls; failure/inconclusive criteria; indexed evidence references. Keep the existing seven-card projection. Unknown keys, code fragments, fabricated field IDs/evidence, unsupported feature kinds, excessive nesting, nonfinite numbers and conflicting source assertions are rejected.

First grammar:
- Level: one sourced field role, with explicit allowed reduction/normalization when justified.
- Change: documented change operation on that role with an explicit bounded horizon; no claim that low-frequency change is an information surprise.
- Relative: comparison within an explicit sourced grouping using a verified group-operator signature. Arbitrary ratios, regressions and residual construction are out of scope initially.

AI selects intent and role requirements, never an executable skeleton or arbitrary operator signature. Deterministic lowering builds a restricted AST using sourced operator definitions and passes the rendered template through existing parse_kernel and bind_template. Unsupported or unavailable constructs fail closed; no silent Relative-to-Level fallback. Syntax descriptions alone cannot prove unspecified types. Identical validated design, compiler version, configuration and evidence generate byte-stable outputs; AI creativity itself is not promised deterministic.

Reuse AI checkpoint/worker isolation, bounded input and cache protocols for an explicitly triggered design task. Production model execution is separate from fake transport tests. Store diagnostics on failure; no unbounded retries or automatic additional Agents.

Design/experiment sidecars are immutable attachments bound to template/version/source and compiler digests, not a new lifecycle or second library. Reuse current publication checks; compilation never self-grants reviewed or measured. If the current reviewer has no applicable admission path, report that integration gap before implementing auto-admission.

### M1 Knowledge Prerequisite

Repair only relevant local source ingestion: normalize documented operator Markdown/structured captures into existing provenance-aware resources; preserve syntax separately from typed facts; extract structured category id/name; validate actual provenance paths. Do not broadly reorganize raw/wiki or label archived user notes official evidence.

Use an explicitly scoped subset to establish executable coverage for supported features, rather than send the entire field catalog to AI. Preserve documented data meaning separately from hypotheses about asset effects. Report three distinct counts: material indexed, required semantic metadata verified, executable bindings. Missing data timing/grain/units remain unknown. Supporting documentation that proves metadata must be explicitly source-bound; no hardcoded invented metadata. If local sources are insufficient, M1 compiler may pass while real-knowledge acceptance remains blocked with the exact missing sources; request separately authorized capture instead of weakening gates.

Offline demo input is frozen resources plus bounded historical summaries (empty or incomplete is legal); output is a valid V2 draft and baseline/treatment design or explicit rejection. M1 does not schedule live pairs. Real-source copies must undergo the same checks, not get patched into success fixtures. No extra model-derived material is represented as measured.

## M2: Hypothesis-First Scout

New runs only, default-off feature flag frozen at Start. Default existing v1/v2 behavior is unchanged. Construct feasible pairs before applying the batch cap; same scope, delay, timing and non-treatment settings. Use documented fixed baseline settings/horizon instead of Scout parameter grids. Existing maximum30 and remaining original authority still apply; odd/insufficient budgets never authorize a half-pair labelled comparison. Pair membership and setting differences are verified after binding and deduplication.

Experiment sidecars attach experiment_id, arm_id, existing candidate_id and baseline_candidate_id to the frozen plan. Do not modify existing candidate identity or CANDIDATE_KEYS. Existing pre-POST persistence, reservations, locks and uncertain-POST recovery remain the execution authority. Restart reuses exact plans. Discovery/Repair retain parameter optimization. A neutralization comparison is sensitivity analysis, not causal identification. Technical failures/429/timeouts are operational outcomes, not falsification.

## M3: Mechanism Evidence Feedback

Build a reproducible derived view from existing identity-verified research records; no hand-editable success database. Retain family/version, role/dataset, scope, available period, exact experiment arms/settings, metrics, attempt counts and source fingerprints. Different scopes/versions or incomparable settings are not pooled as equivalent replications.

Labels: supports_prediction_in_scope, contradicts_prediction_in_scope, inconclusive, operational_failure. Missing measurements or compatible controls mean inconclusive. Positive backtests do not prove economic causality. Select bounded relevant histories including failures/unidentifiable proposals for the next design task; never feed the whole wiki on every iteration. Generated explanations remain hypotheses.

## Knowledge Placement And Human Learning

Keep raw/machine/wiki. Raw holds immutable materials and original research. Machine holds existing ledgers, versioned releases and necessary digest-bound attachments/derived views. Wiki explains conditions -> mechanisms -> constructions -> results -> failure boundaries using existing canonical pages and case reports. No new historical wiki tree or duplicated full catalogs. This feature is not a general history-cleanup migration.

## Performance And Maintenance

Measure model calls, cache reuse, preselection candidate expansion and actual selected candidates in offline tests. M2 should avoid the prior parameter-product pool in its flagged Scout path. Do not promise live request reduction, throughput or quality without live evidence. Reuse existing multisimulation/polling; no changes to those executors. New modules remain pure where possible, with function input/output/type comments. Shared limits flow through existing configuration, not new scattered constants. Use existing code/tests/scripts/docs/runs/output directories; test temporary state must not leak mock/browser/system-profile directories into the workspace.

## Verification And Milestones

M1: test strict designs, conditions influencing construction/experiments, all three feature kinds (or honest sourced rejection), types/vector reduction, metadata/time/scope, deterministic drafts, evidence hashes, duplicate AST/settings, worker failure and no publication authority; runnable offline demo; real-source subset coverage report.

M2: test legal paired differences, invalid arm, insufficient quota, dedup collision, zero pairs, default-off legacy equivalence, frozen replay, Stop/429/unknown POST and no extra submit. Reuse mature recovery tests rather than rewrite recovery.

M3: test reproducible view, attempt counting and incompatible-scope separation, failures retrieval, insufficient control/technical failures, no causal promotion and bounded context injection.

Each milestone uses TDD, scoped independent review at reasoning medium or below, focused and full offline suites, updated architecture/manual and durable todo handoff. Do not claim end-to-end live acceptance from fake transport success. Source changes invalidate existing maintenance proof; do not renew or resume the old run without separate authorization. No commit/push is inferred.

## Out Of Scope

Orchestrator rewrite, Agent framework, LangGraph, arbitrary formula generation, exhaustive Cartesian designs, global AI enrichment of all catalog rows, new service, silent knowledge capture, automatic rule changes, automatic final submission and broad unrelated cleanup are excluded. Cleanup is separately recorded in todo.md and must preserve sensitive files and referenced research.
