# BrainWorkflow V2 Rollout

V2 names the structured economic-hypothesis research path, not a replacement Orchestrator or agent framework. Resource contract 2, design context 3 and the Console protocol have independent version numbers.

## Pipeline

1. Existing indexed sources and bounded research evidence feed `prepare_design_job`.
2. The read-only model worker proposes schema-checked mechanisms, conditions, alternatives and falsifiable tests, not formulas.
3. The deterministic compiler produces exploratory templates and matched baseline/treatment experiments.
4. A separate exact-result review exports publication inputs; immutable semantic publication activates a source-bound release.
5. New paired Scout snapshots freeze the release, sources, settings, bindings and complete experiment arms. Parameter grids remain in later Discovery/Repair.
6. Existing executors preserve Stop, quotas, uncertain POST identity, cooldown and final submission authority. Research records feed scoped mechanism evidence during maintenance compilation, not every Start.

## Local Activation

The repository example keeps `research_policy.paired_scout` false. A deployment may explicitly enable it in ignored `configs/workflow_local.json`:

```json
{"research_policy":{"paired_scout":true}}
```

Console Start freezes this policy; form values cannot override it. Existing runs retain their old snapshots and durable Stop. Disabling the local flag does not roll back a semantic release; use a separately reviewed release for resource rollback, never silently delete its active pointer.

Use the existing desktop launcher. Health must identify the intended workflow/knowledge/runs roots and match the current code revision. Dashboard and fragment responses must agree on loaded revision and actions. This deployment validation does not press Start or create a mission.

## Accepted Scope And Limits

The actual rollout verified one `snt_buzz` USA Delay-1 TOP3000 field with a reviewed `ts_delta` definition. The accepted exploratory pair is `-snt_buzz` versus `-ts_delta(snt_buzz, 5)`, with identical portfolio settings. Actual source-backed readiness and snapshot construction passed without simulations or mission creation.

This is limited semantic coverage, not a claim that every catalog field/operator has complete meaning. Other scopes require their own verified resources. Canonical legacy ledgers and old run evidence remain preserved; the immutable active release selects the reviewed subset.

Higher values implying greater negative sentiment volume is an explicitly indexed hypothesis, not verified numerical encoding. Historical point-in-time availability, units, missing-zero interpretation and measured performance remain unresolved. Conditions are interpretive, not executable filters. No numeric comparison contract means results remain inconclusive with observed differences; correlation is not causal proof.

## Verification And Recovery

Design context references bind exact file bytes and canonical object identity. Context-3 writes compact canonical JSON and rejects byte drift before model execution. Earlier failed or stale jobs remain unchanged and are not automatically retried; extra model calls require explicit budget authority.

Rollout receipts live under the local vault's `machine/reports/`, including prior release identity, reviewed result, source dates, snapshot acceptance, deployment health and model usage. Private vault/runs, local configuration and generated logs are not committed. Workspace `todo.md` remains the interruption ledger, and `milestone.md` remains the architecture entry.

Offline acceptance: 2103 tests completed, two skipped; compileall, architecture/entry checks and whitespace validation passed. Local live-transport performance and strategy quality were not tested, and this deployment grants no WQB call, research resume or Alpha submission authority.
