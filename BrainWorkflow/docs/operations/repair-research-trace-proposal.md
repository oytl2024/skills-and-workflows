# Metric-Driven Repair Trace

User approved implementation 2026-10-13. This document records the design, not
permission to invent operator signatures or expand live research limits.

Each experiment should record:

1. Baseline: parent identity/settings, metric values, failed checks and measurement scope.
2. Diagnosis: primary metric target and an evidence-based economic hypothesis.
3. Controlled change: exactly one change, expected improvement, tradeoffs and falsification criterion.
4. Comparable test: child identity/settings, same scope and measured before/after metrics.
5. Decision: accept, reject or inconclusive; failed assumptions and remaining checks.
6. Reusable conclusion: applicable data/template conditions and counterexamples, compiled later into wiki.

Store concise auditable rationale and experiment evidence, not private model
reasoning. An improved in-sample metric alone is not causal proof or qualification.

Research levers include nonlinear weight redistribution, exposure neutralization,
holding/decay and trading intensity. Uniform positive scaling generally cannot
change normalized long/short balance. Neutralization may remove real signal.
Turnover is a cost proxy, not measured transaction cost. Operator use requires
authoritative signatures, types and compatible platform settings. No new operator
edit is enabled by this proposal; existing supported edits remain unchanged.

Implementation boundary: extend existing Repair decision/comparison
receipts, then compile concise human-readable experiment trajectories during the
separate knowledge-maintenance workflow. Do not introduce another parallel ledger.
