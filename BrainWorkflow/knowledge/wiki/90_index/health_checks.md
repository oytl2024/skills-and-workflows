# Knowledge Base Health Checks

## Weekly Checks

- Every compiled wiki claim should have a source path, experiment link, or user-experience label.
- Every repeated simulation failure should map to a benchmark or workflow rule.
- Every near-miss with strong PnL should have an experiment note and repair status.
- Every new dataset used in simulation should have a semantic note.
- Every submitted or candidate alpha should have a local fingerprint for self-correlation avoidance.

## Integrity Checks

- No hardcoded credentials or API secrets.
- No final submission without user confirmation.
- No alpha enters the candidate submission list before all required checks pass.
- No large external download without explicit user approval.
